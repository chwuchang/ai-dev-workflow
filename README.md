# AI 协同开发工作流框架

一套面向 AI 编程助手的**结构化协同开发工作流**，通过规范化的流程控制、记忆系统和归档机制，让 AI 在复杂项目中稳定、可控地工作。

## 核心理念

- **流程即纪律**：通过检查点（⛔）强制 AI 等待人类确认，杜绝自作主张
- **记忆即上下文**：跨会话持久化关键信息，避免每次对话从零开始
- **归档即知识**：完成的工作自动沉淀为可检索的项目知识

## 目录结构

> **说明**：本仓库根目录的内容，等价于目标项目中的 `.agents/` 目录内容。
> 使用时应将本仓库中的 `workflows/`、`tasks/`、`context/`、`specs/`、`archive/`、`GEMINI.md` 复制到目标项目的 `.agents/` 下。

```
.agents/
├── workflows/          # 工作流定义
│   ├── dev.md          # /dev  — 完整开发流程（11步 + 5个检查点）
│   ├── fix.md          # /fix  — 快速修复流程
│   ├── review.md       # /review — 代码审查流程
│   ├── task.md         # /task — 任务继续执行
│   ├── discuss.md      # /discuss — 自由讨论模式
│   ├── init.md         # /init — 项目初始化
│   └── _templates/     # review 等独立 workflow 的标准输出模板
├── tasks/              # 任务工作区（计划/清单/状态/审查）
│   └── _templates/     # 标准任务模板与使用说明
├── context/            # 跨会话记忆
│   ├── architecture.md # 技术栈与架构
│   ├── active-tasks.md # 进行中的任务
│   ├── feedback.md     # 用户行为反馈
│   ├── user-preferences.md # 用户偏好
│   └── references.md   # 外部资源链接
├── specs/              # 系统行为规范
│   └── _overview.md    # 规范索引
├── archive/            # 完成任务归档
│   ├── _index.md       # 归档索引
│   ├── features/       # 功能开发归档
│   ├── bugfix/         # Bug 修复归档
│   └── decisions/      # 技术决策记录
└── GEMINI.md           # 全局系统指令（角色定位 + 铁律）
```

## 工作流一览

| 命令 | 用途 | 检查点 | 适用场景 |
|------|------|--------|----------|
| `/dev` | 完整开发流程 | 5 个 | 新功能、重构、架构变更 |
| `/fix` | 快速修复 | 1 个 | Bug 修复、小改动 |
| `/review` | 代码审查 | 2 个 | 代码审查、PR Review、质量审计 |
| `/task` | 继续执行 | 0 个 | 从中断处恢复、推进已有计划 |
| `/discuss` | 自由讨论 | 0 个 | 技术探讨、方案讨论 |
| `/init` | 项目初始化 | 0 个 | 首次接入或修复缺失文件 |

## `/dev` 流程概览

```
需求分析 → 技术决策澄清 → 架构设计 → 实现方案 → 任务拆解 → 逐条执行 → 最终审查 → 验证 → 归档
   ⛔1        ⛔2            ⛔3         ⛔4                    (微审查)      ⛔5
```

### 关键特性

- **技术决策澄清**：AI 主动识别隐含决策点，区分阻塞/非阻塞性决策
- **验收标准驱动**：每个任务必须包含可验证的验收断言
- **微审查机制**：每完成一个任务立即审查，而非最后一次性审查
- **任务工作区**：计划、任务清单、状态和审查报告都有固定落盘位置，支持 `/task` 恢复
- **模板驱动执行**：`tasks/_templates/` 提供标准骨架与恢复规则，减少 AI 自由发挥导致的格式漂移
- **审查模板**：`workflows/_templates/` 提供 `/review` 的标准报告骨架，便于稳定做 PR 和代码审查
- **自动归档与记忆提取**：完成后自动沉淀知识，更新项目规范

## 快速开始

### 1. 复制到你的项目

```bash
mkdir -p /path/to/your/project/.agents/
cp -r workflows tasks context specs archive GEMINI.md /path/to/your/project/.agents/
```

### 2. 初始化

复制完成后，让 AI 执行 `/init`。它会检测 `.agents/` 是否完整、补齐缺失文件，并根据项目实际情况填充上下文文件。

### 3. 开始使用

- 开发新功能：告诉 AI 你的需求，它会自动路由到 `/dev`
- 修复 Bug：描述问题，AI 会路由到 `/fix`
- 代码审查：要求 AI 审查文件、模块、PR 或 diff，它会路由到 `/review`
- 继续执行：要求 AI 继续某个已有计划或任务，它会路由到 `/task`
- 技术讨论：直接聊，AI 会自动进入 `/discuss` 模式

## 设计原则

1. **拒绝过度设计** — 只做当前需要的，不为假想未来增加复杂度
2. **简洁优先** — 简单方案能解决的，绝不用复杂方案
3. **以事实为准** — 一切结论基于代码事实，不臆测不假设
4. **务实导向** — 技术选型以解决实际问题为目标

## 适配说明

本框架设计为**工具无关**，可适配不同的 AI 编程助手：

- **Antigravity / Gemini**：将 `GEMINI.md` 配置为系统指令，其他目录复制到目标项目 `.agents/` 下
- **Claude Code**：可转换为 `CLAUDE.md` + commands 格式
- **Cursor**：可转换为 `.cursorrules` + 自定义 commands 格式
