# /task — 任务执行流程

## 触发条件

AI 自动路由或用户显式调用 `/task`。适用于：
- 从上次中断的地方继续
- 执行已通过审核的方案
- 按已有任务清单逐条推进

## 执行步骤

### 1. 读取当前上下文与记忆

- 读取 `.agents/context/active-tasks.md` — 查看进行中的任务
- 读取 `.agents/context/feedback.md` — 用户行为偏好（避免重复犯错）
- 读取对应的 implementation_plan（如有引用路径）
- 确认当前进度

### 2. 确认继续点

- 向用户确认从哪条任务开始继续
- 如果只有一个活跃任务，直接继续

### 3. 逐条执行

- 按任务清单顺序执行
- 每完成一条标记 `[x]`
- 实现前**必须先阅读**要修改的文件
- **每完成一个任务后，立即微审查**：
  - 改动是否满足该任务的验收标准
  - 是否引入编译错误或明显逻辑错误
  - 是否破坏已完成任务的验收标准
- 每完成 3-5 个任务后，进行一次**跨任务一致性检查**
- 发现问题时及时反馈

### 4. 阶段验证

- 每完成一个逻辑分组的任务后，**逐条核对该分组内所有验收标准**
- 全部完成后执行最终验证，确保所有验收标准通过

### 5. 更新进度与提取记忆

- 更新 `.agents/context/active-tasks.md`
- 如果全部完成，执行归档（同 `/dev` 步骤 9-10）
- 检查本次对话中是否有用户纠正/确认/偏好，写入对应 `context/` 文件
