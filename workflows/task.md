# /task — 任务执行流程

## 触发条件

AI 自动路由或用户显式调用 `/task`。适用于：
- 从上次中断的地方继续
- 执行已通过审核的方案
- 按已有任务清单逐条推进

## 任务工作区约定

`/task` 只执行已经存在的任务工作区。每个活跃任务应至少具备：

- `.agents/tasks/<task-id>/plan.md`
- `.agents/tasks/<task-id>/checklist.md`
- `.agents/tasks/<task-id>/status.md`

标准模板位于 `.agents/tasks/_templates/`，用于新建任务工作区或补齐缺失文件。

恢复规则：

- `tasks/_templates/` 下的标准模板缺失时，可以自动恢复
- 活跃任务的 `plan.md`、`checklist.md`、`status.md` 若缺失，**不能凭猜测重建**
- 只有在任务尚未开始执行、且用户明确同意时，才可基于模板重新初始化该任务目录

## 执行步骤

### 1. 读取当前上下文与记忆

- 读取 `.agents/context/active-tasks.md` — 查看进行中的任务
- 读取 `.agents/context/feedback.md` — 用户行为偏好（避免重复犯错）
- 读取对应任务目录下的 `plan.md`、`checklist.md`、`status.md`
- 确认当前进度
- 如果活跃任务缺少关键文件，**不要硬着头皮继续执行**；先告知用户，并切回 `/dev` 重新建档
- 如果缺失的是 `tasks/_templates/` 下的模板文件，可以先恢复模板，再继续判断是否缺少任务实例文件

### 2. 确认继续点

- 向用户确认从哪条任务开始继续
- 如果只有一个活跃任务，直接继续

### 3. 逐条执行

- 按任务清单顺序执行
- 每完成一条标记 `[x]`
- 实现前**必须先阅读**要修改的文件
- 每完成一条，同步更新 `status.md` 中的当前进度与下一步
- **每完成一个任务后，立即微审查**：
  - 改动是否满足该任务的验收标准
  - 是否引入编译错误或明显逻辑错误
  - 是否破坏已完成任务的验收标准
- 每完成 3-5 个任务后，进行一次**跨任务一致性检查**
- 发现问题时及时反馈
- 在任一步骤中，只要触发长期记忆条件，就在当前回复后立即更新对应 `context/` 文件

### 4. 阶段验证

- 每完成一个逻辑分组的任务后，**逐条核对该分组内所有验收标准**
- 全部完成后执行最终验证，确保所有验收标准通过

### 5. 更新进度与提取记忆

- 更新 `.agents/context/active-tasks.md`
- 如果全部完成，执行 `/dev` 中的“最终代码审查 → 验证 → 归档 + 更新规范 → 自动提取记忆”四个阶段
- 检查本次对话中是否仍有尚未落盘的长期记忆，写入对应 `context/` 文件
