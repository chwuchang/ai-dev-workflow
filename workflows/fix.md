# /fix — 快速修复流程

## 触发条件

AI 自动路由或用户显式调用 `/fix`。适用于：
- Bug 修复
- 小功能调整
- 配置变更
- 单文件或少量文件的修改

## ⚠️ 铁律（补充，全局铁律见 GEMINI.md）

1. **修改前必须先读目标文件** — 不能凭记忆改代码。

## 执行步骤

### 1. 读取项目上下文

**必须先读取**：
- `.agents/context/architecture.md` — 技术栈和编码规范
- `.agents/context/feedback.md` — 用户行为偏好（避免重复犯错）
- `.agents/specs/` 下与问题相关的 spec 文件（如有）
- 问题相关的代码文件

### 2. 问题定位

> ⛔ **必须按以下格式输出，缺一不可：**

```
## 已读文件
- `path/to/file1` 第X-Y行
- `path/to/file2` 第X-Y行

## 关键代码引证
[粘贴与问题直接相关的原始代码片段，不是自己编的]

## 问题根因
[基于上述代码事实得出的结论]

## 修复思路
[具体修复方案]
```

- 如果无法引用具体代码行来支撑结论 → **不允许给结论**，必须继续阅读
- 列出的已读文件必须是实际通过工具读取过的，不能是猜的

> ⛔ **检查点**：等待用户确认修复方向后继续

### 3. 执行修复

- 修改前**必须先阅读**目标文件当前内容（不能凭记忆改）
- 修改代码

### 4. 自审查

修改完成后快速检查：
- 修改是否引入新问题
- 是否影响其他模块
- 边界情况是否处理

> ⛔ **必须输出审查结论**，不能跳过

### 5. 验证

- 运行相关测试（如有）
- 手动验证修复效果
- 将验证结果提交用户确认

### 6. 简要归档 + 条件更新规范

- 在 `.agents/archive/bugfix/` 下创建归档文件（≤50行），**必须使用 frontmatter**：
  ```yaml
  ---
  name: Bug 标题
  description: 一句话描述问题和修复方案
  type: bugfix
  date: YYYY-MM-DD
  status: completed
  ---
  ```
- 更新 `.agents/archive/_index.md`
- **条件更新 spec**：如果修复涉及行为变更（不只是代码质量修复），更新对应 `specs/` 文件

### 7. 自动提取记忆

归档完成后，检查本次对话中是否有值得记录的内容：
- 用户纠正/确认的行为 → 写入 `context/feedback.md`
- 新了解的用户偏好 → 写入 `context/user-preferences.md`
- 外部资源链接 → 写入 `context/references.md`
